# GlobalSend &mdash; Practical Project Demonstration Guide for Viva

This step-by-step presentation script is designed for your end-term practical demonstration. Follow these exact steps to showcase every Advanced Java feature smoothly to your examiner.

---

## Preparation (Before Starting)

1. Ensure the application is started:
   ```bash
   cd globalsend-java
   ./run.bat
   ```
   *(Or run: `./mvnw compile exec:java`)*
2. Confirm the terminal displays:
   ```
   [DatabaseConfig] Successfully connected to SQLite database at: jdbc:sqlite:.data/globalsend.db
   [FileExpirationService] Starting periodic background cleaner thread. Interval: 60s
   ============================================================================
     GLOBALSEND IS RUNNING: http://localhost:8080/
   ============================================================================
   ```
3. Open Google Chrome, Safari, or Microsoft Edge to `http://localhost:8080/`.

## Step 1: Landing Page & Architectural Overview (Time: ~1 minute)

1. Point out the **Apple Human Interface Design (iOS 18 / macOS Sequoia)**:
   * Glassmorphism navigation bar with blur effect (`backdrop-filter`).
   * Clean typography, continuous corner radii, and responsive layout.
2. Highlight the **Viva Quick-Access Banner**:
   * Mention the pre-seeded accounts: `alice`, `bob`, `professor`.
3. **What to say to the Examiner:**
   > *"GlobalSend is an enterprise Advanced Java web application. It is built strictly using Jakarta Servlets 6.0, JSP 3.1, JDBC with HikariCP, Concurrency utilities (`ScheduledExecutorService`), and Java NIO for high-performance file streaming."*

## Step 2: Single Secret-Key Cryptography Demonstration (Time: ~1.5 minutes)

1. Click **"Get Started"** or **"Sign In"** in the top navigation bar.
2. Point out that there are no password recovery forms or personal emails required:
   * The user enters a username and a single master secret passphrase.
3. Demonstrate creating an account or clicking the **"Alice"** quick-fill button:
   * Username: `alice`
   * Secret Key: `alice-secret-key-2026`
4. Click **"Unlock Vault"**.
5. The application redirects to `/dashboard`.
6. **What to say to the Examiner:**
   > *"Authentication is powered by PBKDF2 with HMAC-SHA256, 10,000 iterations, and a 16-byte cryptographically secure random salt generated by `java.security.SecureRandom`. Password equality checks are performed using constant-time comparison (`MessageDigest.isEqual`) to eliminate timing attacks. The user's public identity is derived deterministically as a SHA-256 key fingerprint shown on the dashboard."*

4. **What to say to the Examiner:**

## Step 4: Java NIO File Upload & Multipart Streaming (Time: ~2 minutes)

1. Click **"+ New Transfer"** or the **"Upload"** navigation link.
2. In the upload form, show the 3 tabs:
   * 📁 **Upload File** (binary files, images, documents)
   * 📝 **Text Note** (confidential notes, code snippets)
   * 🔗 **Web Link** (secure bookmarks with notes)
3. Select **Upload File**:
   * Title: `Java NIO Verification Spec`
   * Select or drag-and-drop any PDF, text, or image file.
   * Set Auto-Expiration Lifetime to **24 Hours**.
   * Tags: `nio, test, report`.
4. Click **"Save to Vault"**.
5. The file is uploaded and the dashboard reloads with the new item card!
6. Open a terminal or file explorer and show `globalsend-java/.data/uploads`:
   * Point out the physically saved file named with a UUID prefix to prevent collisions.
7. Click the **"Download"** button on the card:
   * Notice the browser downloads the file with the original filename preserved via `Content-Disposition`.
8. **What to say to the Examiner:**
   > *"File uploads are processed using Jakarta Servlet's `@MultipartConfig` and Java NIO. `FileUtil.java` verifies that target paths are safely canonicalized to prevent Path Traversal attacks. Files are streamed to the client using zero-copy byte transfers via `Files.copy(path, response.getOutputStream())`."*

## Step 5: Direct Messaging & Transaction Management (Time: ~1.5 minutes)

1. Click **"Direct Chat"** in the navigation bar.
2. Type recipient username: `bob` and click **"Chat"**.
3. Type a message: `"Hey Bob, testing ACID transaction atomicity in GlobalSend!"` and click **"Send"**.
4. The message appears in the chat thread with a blue Apple bubble.
5. In another incognito window or browser, log in as `bob` (Key: `bob-secret-key-2026`).
6. Navigate to **Direct Chat**: Bob sees Alice's message in real time!
7. **What to say to the Examiner:**
   > *"Direct messages demonstrate multi-table ACID transaction management in `ChatDAO.java`. We invoke `conn.setAutoCommit(false)` to ensure both the message insertion and the conversation's `updated_at` timestamp occur atomically. If any error occurs, `conn.rollback()` executes, guaranteeing database consistency."*

---

## Step 6: Concurrency Cleaner Demonstration (`ScheduledExecutorService`) (Time: ~1 minute)

1. Point to the terminal running the server.
2. Highlight the periodic log entry:
   ```
   [FileExpirationService] Found 0 expired vault item(s) for cleanup.
   ```
3. **What to say to the Examiner:**
   > *"GlobalSend features autonomous file lifecycle management. A background daemon thread managed by `ScheduledExecutorService` runs every 60 seconds. When an item's expiration timestamp passes, this cleaner thread unlinks the physical file from disk via `Files.deleteIfExists`, restores the user's storage quota, and batch-deletes the records from the database."*
